# Calculated DPS in Completion methods — 3.0.20

The Completion methods card previously searched master-plan rows for a matching assignment/variant/location. A planner can use a different completion variant, or no row yet, so an editor-only selection could display **Configured timing retained** with an incorrect generic measured/manual explanation even when DPS timing was selected.

The editor now resolves its own selected assignment and variant through `configuredMethod` and `withCalculatedTiming`, in a dedicated `method-timing` worker. It does not rely on master results or change hunt targets. The result displays calculated DPS, expected per-creature throughput time, selected weapon, location/style and the existing timing notes. The editable DPS field is labelled **Manual fallback DPS** when automatic DPS timing applies; its saved value is not replaced by a derived result.

The method card shows its own loading percentage/current creature, cancellation and retry states. It does not infer loading from unrelated planner/guide workers. Changing the method or character cancels pending work; late results/progress are ignored. Completed previews are cached by character, combat identity, assignment and configured method, with a bounded 32-entry session cache. Hunt-goal or point-balance changes do not alter that identity. The shared combat cache is restored/updated so preview work can be reused. Leaving the page cancels unfinished editor work. Computed previews are never saved in character exports.

Retained timing now explains its actual reason: automatic timing disabled, a measured kills/hour or whole-task rate, an explicit manual-DPS override, missing required gear, unsupported location/mapping, or boss/phase/switch timing. **Use calculated DPS** enables automatic combat timing for the character and switches only the edited method to DPS timing with its manual override off. Existing manual DPS/rate values and other methods' measured/manual choices are preserved; the UI explains the character-wide setting. Required protection, encounter limitations and the underlying DPS/kill-time formulas are unchanged.

## Verification

Production build and strict TypeScript passed. All 414 JavaScript tests passed, including twelve selected-method regressions. These reproduce the Blue dragon selection with a Basilisk Knight hunt, exercise the real worker without creating master plans, check disabled/measured/manual/missing-gear/boss reasons, cache identity, stale completion/progress rejection, cancellation, failure/retry, leaving/returning, completed-result reuse and status rendering. Existing timing, family-filter, ranged-ammunition, planner and simulation checks remain passing.

Synthetic localhost browser QA added an Anti-dragon shield to the existing test bank, opened Blue dragons → Blue dragon while the hunt remained configured for Basilisk Knights, enabled calculated timing and observed a local 0% selected-method loading state followed by **5.717 DPS**, **20.40 seconds** and Ancient staff. The manual override displayed its actual reason; Use calculated DPS restored the derived result without changing the saved fallback DPS of 5. Baby blue dragon showed its own **6.455 DPS / 8.72 seconds / Toxic blowpipe**; returning to Blue dragon restored the correct result. These values describe that synthetic gear/skill/location scenario, not the user's real character. Native app interaction was not repeated, and real character files/running applications were untouched. Distribution/source parity and ZIP integrity are checked during release packaging.
