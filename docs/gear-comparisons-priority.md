# Gear comparisons and priority preparation — 2.9.3

Every mapped, supported recommendation in the owned, mid-level and max gear grids offers a hover/focus panel and an explicit information button. It preserves the item’s Wiki link. Clicking the information button pins the panel; clicking again, Close, Escape or outside dismisses it. The comparison table scrolls independently and stays within the viewport.

Each same-slot owned alternative is recalculated against the selected NPC/form/location with the other gear fixed. The displayed recommendation is the baseline. The table reports whole-setup single-target DPS, its delta, aggregate pod DPS when applicable, individual prayer and all five equipment defensive bonuses, and the defensive-bonus average used by the fallback ranking. That average includes generic melee alongside explicitly listed ranged/magic attacks; it does not model damage taken or prayer drain. Owned snapshot/group/manual availability follows the existing bank rules. Skill-ineligible or incompatible alternatives remain visible with an explanation and no fabricated DPS. Unowned curated baselines are labelled.

The reason distinguishes required equipment, prayer/defensive armour fallback, bounded DPS selection and curated templates. Weapon alternatives may use another compatible attack/spell within the selected combat family, which is identified in the row. Other equipment is held fixed, so a two-handed alternative cannot silently discard the current off-hand. Set/autocast dependencies are validated by the shared engine. The tooltip can identify a better one-slot alternative missed by the bounded optimiser; it does not claim global optimality. Charges, item quest/diary unlocks, real incoming damage and exact survivability remain outside this comparison.

Comparisons are lazy, use a separate cancellable worker, and are cached by profile/guide context, tier, family and slot. A changed profile, import or guide choice clears the cache; removed anchors dismiss it. Profile changes cancel all old calculation jobs. In-flight guide results carry their original context signature so an old guide cannot overwrite a newer selection.

On startup/profile changes/imports/recalculation, the main worker first prepares hunt target methods and the selected guide. The active guide runs first when visible; otherwise hunt targets run first. Target methods use the same configuration merge as ordinary planner rows. They populate the same optimiser cache before master work. Masters offering selected assignments and target rows are prepared first with stable ordering within each priority group. Returned rows retain catalogue order, keeping planning sums/tie order unchanged. Priority preparation is included in the progress denominator, guide results are published immediately after preparation, and each master is published when it finishes. Full plan ranking is still finalised after every master finishes; early plans are visibly accompanied by progress.
