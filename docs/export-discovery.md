# RuneLite export discovery — 3.0.1

## Behaviour

Entering the wizard’s Import files step starts one desktop search per character per app session. The fixed default is the Electron home directory plus `.runelite/character-exporter`, matching Character Export’s `RuneLite.RUNELITE_DIR/character-exporter` layout. Discovery checks immediate character folders for the six supported exports. A single matching folder produces a review without a dialog. Several matches, no matches, an unavailable search directory or an excessive directory listing lead to a native directory picker. The picker starts at character-exporter when it exists, otherwise `.runelite`, otherwise the user home. It does not create directories. Explicit folder selection bypasses discovery. Cancellation preserves saved character facts.

The renderer only requests `auto` or `choose`; it cannot send an arbitrary filesystem path. The trusted main-process handler validates the sender and packaged document, then obtains the directory from the native picker. It reads only character.json, bank.json, inventory.json, equipment.json, quests.json and diaries.json. Other files and recursive backups are not read. Linked character directories are excluded; export files must be regular files. Reads have a 5 MB per-file and 20 MB aggregate bound, check file identity and detect a file changing during its read. These checks are not an atomic snapshot across all six files. Existing account/session validation still applies. Discovery never imports facts automatically.

The web version cannot inspect arbitrary local folders or force its picker to a user-home path. Its folder picker accepts a character folder or the export root. Root selection with multiple characters shows a character selector; only selected contents are read. Name grouping accepts at most the selected directory and its immediate children, ignores unrelated/nested files, and bounds the file listing. No folder handles or raw exports are persisted or uploaded. Individual-file import remains available.

Bank & gear has a shortcut to the same import review. The wizard can retry discovery or choose a different folder. A failed or superseded read cannot apply facts; normal import review and manual-override preservation remain in place. Setup undo/character changes also clear pending folder data. Exporting from RuneLite remains the user’s responsibility: open the bank and use Sync Available before importing. This is on-demand discovery, not a watcher or background account sync.

## Evidence and limits

- Source layout checked against the locally retained Character Export source: `CharacterStateExporterPlugin.java` defines the output directory from `RuneLite.RUNELITE_DIR`; its README documents the per-character folder.
- Filesystem integration tests use isolated temporary homes: singleton detection, multiple-character picker root and selected-only reads, explicit choice/cancellation, missing-directory fallback without creation, wrong modes/empty selections, size bounds and linked-directory rejection.
- Browser grouping tests cover multiple characters, direct selection with nested backups, unsafe paths and excessive listings. Main-process tests reject foreign senders/documents before filesystem access.
- A read-only discovery against the actual local exporter folder found all six expected files. The ordinary parser accepted 24 base skills, 47 relevant quest states and three elite diary flags. Nothing was applied or uploaded by that check.
- Browser UI: selecting one synthetic folder produced a six-file review without choosing individual files. Selecting a synthetic export root exposed two characters; choosing First succeeded even though Second contained invalid JSON, confirming the other contents were not parsed.
- Validation: full JavaScript suite passed (251/251); TypeScript passed. Browser singleton/root-folder flows and the actual local read-only discovery passed. Native picker directory/default/cancellation and sender checks passed integration tests. Packaged UI smoke-test results are recorded before release. Browser directory location defaults depend on the browser; only the native Windows picker can be directed to the RuneLite directory.
