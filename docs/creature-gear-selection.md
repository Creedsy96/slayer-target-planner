# Selectable creature gear — 3.0.21

The slot comparison in **Best in your Slots** now includes **Use item** actions. Selections are saved per character, creature variant and combat family. This supports intentional downgrades as well as upgrades. Selected slots remain fixed through weapon screening, set seeds, slot refinement and prayer/defensive armour fallback; remaining slots are optimised normally. Empty slots can also open the comparison. **Reset Melee/Ranged/Magic gear choices** returns that style to automatic equipment selection.

Only available, wearable items with a supported comparison can be selected. Required creature/location equipment remains enforced. Ranged weapon rows save the exact weapon/ammunition pair, including enchanted crossbow bolts and loaded blowpipe darts. Two-handed weapons remove optional off-hands, while mandatory protection prevents incompatible swaps. If a later bank/level/access change makes a saved choice unusable, the style explains the problem and offers its reset control. Curated example sets remain comparison references, rather than editable character equipment.

Selecting gear also selects that combat style and calculated timing for the creature's assignment methods. The per-method `useSelectedGear` flag allows this without changing the character-wide automatic-timing setting. Manual DPS and measured rate values, task delay, travel, extensions and location rules are retained as fields; choosing measured/manual timing again still takes priority. Boss/phase/switch encounters retain configured full-fight timing. Gear overrides are optional validated fields in existing schema-2 character exports; no bank ownership, purchased reward or account fact is fabricated. Older characters need no migration.

Gear overrides enter the individual creature/style combat cache key, not the character-wide combat identity. Selected-method preview keys include that creature's choices too. A dedicated `gear-selection` worker refreshes the selected guide creature and the masters offering its assignment. Reset/Turael or Mazchna boosting dependencies extend that affected-master set when a filler task changes. Existing combat results for other creatures stay reusable; the worker does not warm every creature. Master optimisation and extension comparisons use the updated task timing and can consequently revise block/skip choices and rankings. Previously completed simulations for affected masters are invalidated, rather than silently retained with old timing.

The UI merges refreshed master plans into the existing list. Unaffected plans stay present. Pending changes accumulate if another creature is edited before the worker completes. Worker identity checks reject cancelled responses; an initial planner run cannot overwrite newer refreshed master plans with its older character snapshot. Progress shows a percentage and the current creature/master. General character edits and explicit full recalculation still use the normal full-plan workflow.

## Verification

Production build, strict TypeScript and all **424 JavaScript tests** passed. Ten new regressions cover forced downgrade/upgrade/reset and task-time changes, armour fallback, style/creature isolation, export round trips and invalid imports, exact crossbow/blowpipe ammunition, two-handed equipment and mandatory shields, per-method timing with character-wide timing disabled or unset, local combat/preview cache invalidation, affected-master/filler dependencies, and the real scoped worker. The warmed-worker regression observes new DPS searches only for Hellhound, publishes only affected master plans and verifies unchanged combat minutes for unrelated tasks.

Synthetic localhost browser QA used **Unlock warning QA**, leaving native applications and real character data untouched. A Hellhound melee downgrade from Abyssal whip to Dragon scimitar changed **4.047 DPS / 30.63 seconds** to **3.467 DPS / 35.47 seconds**. A manually selected body armour piece remained fixed; ranged and magic setups retained their previous results. Choices persisted after reload. Upgrading restored the original melee metrics; resetting restored automatic prayer armour. Selecting **Rune crossbow + Ruby bolts (e)** retained that exact pair and displayed **3.760 full-HP DPS / 35.34 seconds**, with the specific HP-dependent expected kill time. Local scoped progress and completed master-plan reuse were observed, with no browser error logs. These numbers describe the synthetic fixture, not any player's bank or universal weapon ranking. Packaged source/assets and ZIP integrity are verified during release assembly; native live-app interaction was not run.
